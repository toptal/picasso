### Form

- upgrade the final-form ecosystem to the versions that support React 19: `final-form@^5.0.1`, `final-form-arrays@^4.0.1`, `react-final-form@^7.0.1`, `react-final-form-arrays@^5.0.0` and `react-final-form-listeners@^3.0.1`. The majors are upstream's Flow-to-TypeScript rewrite: the runtime behavior of the re-exported `FieldArray`, `useFieldArray`, `OnChange`, `OnFocus`, `OnBlur` and `ExternallyChanged` is unchanged, the re-exported final-form **types** change as listed below
- a `FieldArray` and `useFieldArray` are now Picasso's own typed wrappers over `react-final-form-arrays` (same props, same behavior): `<FieldArray>` stays a valid JSX element on `@types/react` 17 and 18 — upstream 5 declares its component as returning `ReactNode`, which only `@types/react` 19 accepts from a component — `useFieldArray<Item>()`, `FieldArrayRenderProps<Item>` and `FieldArrayProps<Item>` keep their item type parameter (the second, element type parameter of `react-final-form-arrays@3` was never used and is gone), and `fields.update(index, value)` is typed again: it always existed at runtime, upstream 5's declaration left it out. `FieldArrayMetaState` and `UseFieldArrayConfig` are exported alongside. The wrappers also keep subscribing the array field to every state key: `react-final-form-arrays@5` narrowed its default subscription to `length`, `value` and `error`, which leaves `meta.dirty`, `meta.touched`, `meta.submitting`, … `undefined` after mount — pass `subscription` to opt into the narrower one
- **consumer action (types)**: `FormProps` no longer carries react-final-form 6's `[otherProp: string]: any` index signature, so extra props passed through `<Form>` or a wrapper typed `FormProps & …` now error — declare the props the wrapper accepts (they still reach the render props at runtime); `FormRenderProps['initialValues']` is `Partial<FormValues> | undefined`, and the `FormState` and `FieldMetaState` booleans (`dirty`, `submitting`, `touched`, …) are optional, matching what final-form fills for a subscription — read them as `initialValues ?? {}` and `Boolean(meta.touched)`; a `@ts-expect-error` on a `FieldArray` render prop that used to mis-type now reports as unused
- **consumer action**: `react-final-form` is a regular dependency of this package and its React context is instance-bound, so apps that also depend on `react-final-form` directly must move to `react-final-form@^7` / `final-form@^5` in the same upgrade. Staying on `^6` yields two library instances, and `useForm`/`useField` used inside a Picasso `<Form>` then throws `"... must be used inside of a <Form> component"`
- `react-final-form@7` derives checkbox/radio `checked` from `parse` instead of `format` — consumers passing `format`/`parse` to `Form.Checkbox` or `Form.Radio` should re-verify checked-state behavior. Hidden checkbox inputs now render `value=""`, so consumer snapshots covering `Form.Checkbox` need a one-time regeneration
- fields register in an effect under `react-final-form@7` and render twice on mount (previously once) — visually inert, but render-count assertions in consumer tests will shift
- a field rendered without a `name` fails while mounting under `react-final-form@7`: it reads the field's initial value with `getIn(initialValues, name)`, gets the whole `initialValues` object back and calls `form.change(undefined, …)`, which throws `"Cannot call setIn() with undefined key"` whenever the form has `initialValues` or the field an `initialValue` (`react-final-form@6` tolerated the missing name until the first change). Development builds now throw a descriptive `[picasso]` error at the field instead; test fixtures that wrap a field must forward `name`
- a `FieldArray` mutators (`fields.push`, `fields.remove`, …) notify the form synchronously — a handler that runs during render (a mocked child calling `remove` while rendering, for example) now triggers React's "Cannot update a component while rendering a different component" warning; call the mutators from event handlers and effects
- `react-final-form-listeners@3.0.1` ships a broken `types` path, corrected by a pnpm patch for this repository's build; a consumer install resolves the package as untyped until upstream ships the fix, so `OnChange`, `OnFocus`, `OnBlur` and `ExternallyChanged` type as `any` there
- drop the `@types/react-final-form-listeners` dev dependency — the package now ships its own types
